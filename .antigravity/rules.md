# 專案特定細則：智慧相片整理助手 (Smart Photo Organizer Rules)

> [!IMPORTANT]
> 本專案嚴格遵循「全域大腦 v2.1.0 (Tech Lead)」。所有腳本邏輯、註解與配置說明必須 100% 使用台灣繁體中文。請保持直接、專業的 Tech Lead 溝通口吻，去除 AI 感。

## 1. 核心業務邏輯 (Business Logic)
- **智慧分類與歸檔**：專注於利用 Python (`main.py`) 高效解析相片的 EXIF 數據（如拍攝日期、GPS、裝置型號），並將其自動分類至對應的資料夾結構。
- **配置驅動 (Config-Driven)**：所有可自訂參數（如來源資料夾、目標資料夾、分類規則、副檔名過濾器）必須嚴格抽離至 `config.json` 中，確保主程式乾淨俐落。

## 2. 系統整合與隱藏執行 (System Integration)
- **無干擾背景執行**：為了提供極致的使用者體驗，必須利用 `start_silent.vbs` 包裝 `start_organizer.bat`，確保 Python 腳本在 Windows 背景靜默執行，絕對不允許彈出礙眼的 CMD 黑視窗干擾使用者。
- **路徑防禦**：在 VBS 與 BAT 腳本中，路徑解析必須支援包含空格或特殊字元的絕對/相對路徑，確保跨設備執行的穩定性。

## 3. 防禦性設計與 IO 安全 (IO Safety & Resilience)
- **零資料遺失原則**：在執行檔案搬移 (`shutil.move`) 或複製時，若遇到檔名衝突，**嚴禁覆蓋原檔**。必須自動在檔名後綴加上流水號 (如 `_1`, `_2`)。
- **異常防護**：讀取 EXIF 數據時，必須妥善處理損毀的圖片檔案、遺失 EXIF 標籤或不支援的格式，發生錯誤時應記錄 Log 並跳過，絕不允許程式直接崩潰。

## 4. 效能優化 (Performance)
- **批次處理與多執行緒**：面對數以千計的照片，必須實作批次讀取機制。若情況允許，應導入 `ThreadPoolExecutor` 進行並行處理，最大化磁碟 IO 與 CPU 效能。

## 5. UI/UX (Terminal & Logging)
雖然本專案為背景執行，但如果未來擴充了任何設定介面 (GUI) 或 Log 輸出：
- 必須遵循「極致美學」，介面要具備現代感，排版俐落。
- Log 記錄必須清晰易讀，時間戳記與錯誤訊息一目了然，並全數使用台灣繁體中文。
